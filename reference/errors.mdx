---
title: Error catalog
description: Every custom error code of the five programs, generated from the published IDLs, with causes checked against the program source.
---

Anchor numbers each program's custom errors from 6000, so one code means different things in different programs. Always read a code together with the program ID that raised it. Wallets and RPC errors often show the code in hex: `custom program error: 0x177c` is 6012.

The tables are generated from the [published IDLs](/build/idls-and-pdas#idl-files), so the codes match the deployed programs. The Message column is the program's own text, as it appears in transaction logs. A cause is given where it was checked against the program source.

## mint-redeem

| 6016 | `0x1780` | `InvalidWeight` | `Invalid weight - must be between 1 and 10000` | A collateral weight of 0 or above 10,000 bps. |

## Anchor errors below 6000

Anchor raises its own errors during account validation, before the program's code runs. The common ones on mint and redeem:

| Code | Name | Cause and fix |
|---|---|---|
| 2001 | `ConstraintHasOne` | An admin instruction signed by a key other than `market.authority`. |
| 2012 | `ConstraintAddress` | The `oracle` account isn't `market.oracleAddress`. Wrong `longMint`, `shortMint` or `collateralVault` accounts raise `InvalidAmount` (6001) instead. |
| 3012 | `AccountNotInitialized` | A user token account (cUSDC, L or S) doesn't exist yet. Create the ATA first. |

## How errors surface in clients

Anchor turns a failed transaction into an `AnchorError` that carries the code, its name and the program that raised it:

```typescript
import { AnchorError } from "@coral-xyz/anchor";

try {
  await program.methods.mintPaired(amount).accountsStrict(accounts).rpc();
} catch (e) {
  if (e instanceof AnchorError) {
    console.log(e.error.errorCode.code);   // "TwapNotAvailable"
    console.log(e.error.errorCode.number); // 6012
    console.log(e.program.toBase58());     // the program that raised it
  }
  throw e;
}
```

When you simulate with `@solana/web3.js`, `AnchorError.parse(logs)` reads the same fields from the logs. The raw log line looks like this:

```
Program log: AnchorError thrown in programs/mint-redeem/src/lib.rs:2581. Error Code: TwapNotAvailable. Error Number: 6012. Error Message: TWAP price not available - keeper has not updated.
```

## Common error sequences

### Mint or redeem fails with `TwapNotAvailable` (6012)

The market's price is 0 or more than 300 s old. The keeper doesn't push prices while the underlying market is closed (for equities, nights and weekends), so mint and redeem stay closed until it reopens. The bin books keep trading in the meantime. If it happens during market hours and persists, check #announcements on [Discord](https://discord.gg/U5hPCB8ufJ), where the team posts outages, or ask in #help.

### Mint or redeem fails with `MintNotAllowedInStress` or `RedeemNotAllowedInStress`

The market is in `Stress`, which blocks both mint and redeem on every live market. Read `market.riskState` and surface it to the user as "mint and redeem paused". The bin books stay open.

### Redeem fails with `InvalidAmount` (6001)

Both `l_amount` and `s_amount` must be above 0: there is no single-leg redeem. Sell a lone leg on its bin book, or through a committed order on QQQ, SPY and XAU. The same code also covers an amount above the outstanding supply and a token account whose mint doesn't match the market.

### Mint or redeem fails with `BelowMinimum` (6019)

A mint needs a deposit of at least 10 cUSDC (`10_000_000` base units). A redeem needs both legs together to be worth at least 10 cUSDC at the redeem NAVs.

### Mint or redeem fails with `Unauthorized` (6021)

`devTokenAccount` must be a cUSDC token account owned by `market.feeRecipient`. Derive it with `getAssociatedTokenAddressSync(cusdcMint, market.feeRecipient, true)`; the `true` matters because a fee recipient can be a PDA.
