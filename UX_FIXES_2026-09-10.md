## Integration review and verification

The lead reviewed the implementation and tightened several cases before the final build:

- Failed refreshes now label retained yield/TVL/APR values as **last known**, rather than silently treating cached data as current. Missing rates do not become a projected zero. Retry controls avoid restarting an already-active fetch.
- History fetch failures propagate to React Query while cached bars remain available, so the last-known-history warning is reachable. No replacement prices or candles were fabricated.
- Pool-book read failures are explicitly exposed, rather than treated as proof that a pool is absent or disabled.
- Mint short-leg decay and reference-update information remain visible before the action; secondary yield details alone are collapsed. No new freshness threshold or transaction guard was invented.
- Landing restoration waits for dynamic content size changes, preserves Next history state, cancels its observers/frames, and distinguishes Back from an explicit Home action.
- Tablet app navigation uses a complete second row rather than a squeezed center group. SEO mobile navigation uses the existing Radix dropdown with keyboard/Escape behavior and an always-visible network-aware CTA.
- Faucet prerequisites appear before its action, the countdown switches cadence near expiry, and sub-minute time is shown in seconds. Faucet is crawlable so its explicit noindex can be read.
- Primary asset/trade/wallet CTAs reuse the existing contrast-safe button style. Pool-reference prices are labeled separately from NAV without changing their calculation.
