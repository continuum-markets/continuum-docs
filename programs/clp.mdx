---
title: clp
description: Continuous Liquidity Provider. The protocol's cUSDC vaults, the native bin books and committed orders.
---

The CLP program holds the protocol's market-making capital and runs both trading venues: committed orders, which fill at the next price push while a market is open, and native bin books, which fill instantly while its price is stale. It also mints and redeems its own L+S inventory through CPI into mint-redeem. A single `GlobalClp` PDA tracks funding and per-market allocations, and its cUSDC vault is the protocol treasury. Each market has a `Clp` PDA with its inventory, swap guards and committed-order spread, plus two `Pool` PDAs, one bin book per side.

```
Devnet ID: 8xauDRjw9XRyk4FE3hW1JKjD8nC87gfr59Xig1dJqLES
```

Anyone can call `pool_swap`, `commit_swap` and `settle_swap`, and anyone can send `cancel_swap` once an order has expired. `clp_swap` is retired and always fails. The sections below give the signer every other instruction requires, usually `global_clp.authority`, the market's `clp.authority` or the pool's `pool.authority`.

## The two venues

| Venue | Instructions | When | Price | Fee |
|---|---|---|---|---|
| Committed order | `commit_swap`, then `settle_swap` | While the market's price is live | NAV ± `max(commit_spread_bps, 10)` bps at a price push after the commit | The spread |
| Bin book (instant) | `pool_swap` | Only while the market's price is stale | Walks the keeper's posted bins out from the book centre, with real slippage | None; you pay the bin spread |

A committed order fills at a price pushed after the commit, so the trader never trades against a quote seen before committing. Since 11 Oct 2026 committed orders are the only venue while a market's price is live, on every market except MSTR. `pool_swap` fills only while the market floats (its risk state isn't `Normal` and its last push is more than 300 s old) and fails with `PoolClosedWhileLive` otherwise. The keeper sizes the bin books to expected demand. The instant oracle swap, `clp_swap`, was retired the same day. See `SwapGuardsState` below.

### `SwapGuardsState`

Stored in `Clp.swap_guards` and set with `configure_swap`. The all-zero default leaves committed orders off. `settle_swap` applies the staleness, confidence and deviation limits and the collateral floor.

| Field | Type | Purpose |
|---|---|---|
| `enabled` | bool | Required by `commit_swap` (`SwapDisabled`). `pool_swap` ignores it |
| `frozen` | bool | Blocks `commit_swap` and `settle_swap` (`SwapFrozen`). `pool_swap` and `cancel_swap` ignore it |
| `spread_bps` | u16 | Spread of the retired `clp_swap`. No live instruction reads it |
| `max_staleness_secs` | i64 | Maximum age of the Market price, in seconds (`OracleStale`) |
| `max_confidence_bps` | u16 | Maximum `Market.oracle_confidence`, in bps of price (`OracleConfidenceTooWide`) |
| `max_deviation_bps` | u16 | Maximum move from `swap_prev_price`, in bps (`OracleDeviationTooLarge`) |
| `window_cap_usd` | u64 | cUSDC notional allowed per window on `pool_swap`; 0 means no cap. Committed fills don't count |
| `window_secs` | i64 | Window length |
| `collateral_floor_bps` | u16 | Minimum market collateral ratio, at the settle price, for a committed fill |

As of 11 Oct 2026, 13 markets (all but MSTR) have guards enabled and not frozen, with the same limits: a 600 s staleness limit, a 5,000 bps confidence limit (off in practice), a 10,000 bps deviation limit (off; `update_risk_state_v2` already refuses a move of more than 25% per push) and a 10,000 bps (100%) collateral floor. Their spread and window cap were left as they were: QQQ, SPY and XAU keep a 30 bps spread and a cap of 1,000,000 cUSDC per hour, and the other markets have no cap. MSTR's guards are off, so `commit_swap` reverts there with `SwapDisabled`.

### `Pool` PDA

```
seeds = [b"pool", market, [side]]    // side: 0 = long, 1 = short
```

Two per market, so 28 for the 14 live markets. Each is a native bin book for one synth leg against cUSDC. The whole book lives in the account (up to 16 bins a side, `POOL_MAX_BINS`), so bins cost no extra rent. The pool PDA's two associated token accounts hold the reserves: synth for the asks and cUSDC for the bids.

| Field | Type | Purpose |
|---|---|---|
| `authority` | Pubkey | Signer for `set_pool_shape`, `configure_pool_geom` and `realloc_pool` |
| `market` / `side` | Pubkey / u8 | Binding |
| `synth_mint` / `usdc_mint` | Pubkey | Pair mints |
| `base_price_1e6` | u64 | Book centre (1e6). The keeper sets it from NAV, shifted for its inventory |
| `step_bps` | u32 | Core bin step (`r = 1 + step_bps/1e4`) |
| `num_bins` | u8 | Bins per side (at most 16) |
| `asks` | `[u64; 16]` | Synth reserve per ask bin, above the centre |
| `bids` | `[u64; 16]` | cUSDC reserve per bid bin, below the centre |
| `enabled` / `frozen` | bool | `pool_swap` needs `enabled` and not `frozen`. The first `set_pool_shape` sets `enabled`; no instruction clears it or sets `frozen` |
| `shape_updated_at` | i64 | Unix time of the last reposition |
| `bump` | u8 | PDA bump |
| `wing_step_bps` | u32 | Wing step for the 2-zone geometry (0 = uniform ladder) |
| `core_bins` | u8 | Number of fine core bins before the wings start |

There is no pool kill switch. Once a pool has a shape, nothing can disable it, though it fills only while its market floats (see `pool_swap` below).

**Bin geometry.** Ask bin `i` sits at `base · r^(i+1)` and bid bin `i` at `base · r^-(i+1)`. The centre itself is an empty mid, so the smallest round trip costs about two steps. With 2-zone geometry, the first `core_bins` steps use `step_bps` for fine pricing near the centre. The rest use `wing_step_bps`, so the same 16 bins can span a large move.

### `Order` PDA (committed orders)

```
order:  seeds = [b"order", user, market, nonce_le_u64]
escrow: seeds = [b"escrow", order]      // token account owned by the order PDA
```

Each order records what the user escrowed and when, and the fill uses a price pushed after `created_at`. The account is 117 bytes, with every field at a fixed offset.

| Field | Offset | Type | Purpose |
|---|---|---|---|
| `user` | 8 | Pubkey | Order owner |
| `market` | 40 | Pubkey | Bound market |
| `side` | 72 | u8 | 0 = long, 1 = short |
| `direction` | 73 | u8 | 0 = buy synth, 1 = sell synth |
| `status` | 74 | u8 | 0 = pending, the only stored state |
| `bump` / `escrow_bump` | 75 / 76 | u8 | PDA bumps |
| `amount_in` | 77 | u64 | Escrowed base units (cUSDC for buys, synth for sells) |
| `min_out` | 85 | u64 | Slippage floor; a miss at settle refunds instead of reverting |
| `created_at` | 93 | i64 | Commit time; settle needs `twap_updated_at > created_at` |
| `expires_at` | 101 | i64 | `created_at + 180`; settle owns ≤, cancel owns > |
| `nonce` | 109 | u64 | Client-chosen seed |

A client can find a wallet's orders with `getProgramAccounts` memcmp filters on `user` (offset 8) or `market` (offset 40). The keeper finds every pending order in one call, filtered on the 117-byte size, the `Order` discriminator and `status = 0` at offset 74. Every terminal path (fill, refund, cancel) closes both the order and the escrow and returns all rent to the user, so a second settle attempt fails at account load.


One per cluster (`58JeHAcMAAyEZWusVqmvoFNVqh37cTkmfbbP6bMHExWR` on devnet, 210 bytes). It holds the limits on `admin_withdraw` and is created by `init_treasury_policy`. It replaced the `AdminWithdrawWindow` account, which the upgrade of 11 Oct 2026 removed.

The live policy on 11 Oct 2026, with nothing pending:

- Burst: 230,617.53 cUSDC, one hour of refill.
- Delay: 24 h.

A fill's spread capture is its distance from the book centre: cUSDC paid minus synth × `base_price_1e6` on a buy, and synth × `base_price_1e6` minus cUSDC received on a sell.

## Instructions

### Swaps

#### `pool_swap(params: PoolSwapParams)` (anyone)

`PoolSwapParams { direction: u8, amount_in: u64, min_out: u64 }`. Direction 0 buys synth with cUSDC, and 1 sells synth for cUSDC. A buy walks the ask bins up from `base·r`; a sell walks the bid bins down from `base/r`. The handler decrements reserves in place, so the stored book always matches the vault balances, and partial bin fills round in the pool's favour. If the book runs out first, the swap fills what it can and takes only what it used. There is no swap fee.

The pool must be enabled and not frozen (`SwapDisabled`), and `base_price_1e6` must be nonzero (`OracleStale`). The market must be floating: its `risk_state` isn't `Normal` and its `twap_updated_at` is more than 300 s old, the age at which mint and redeem freeze (`PoolClosedWhileLive` otherwise). Something must fill (`InsufficientFunds`), the output must reach `min_out` (`SlippageExceeded`), and the fill must fit the `Clp` window cap (`WindowCapExceeded`). `pool_swap` doesn't read `swap_guards.enabled`, `frozen` or the oracle guards: it trades on the book as posted. Off-hours the keeper keeps a capped free-float book, with a guard that can only pull bins on the stale side. Until 11 Oct 2026 the books traded at any hour.

Accounts, in order:

| # | Account | Notes |
|---|---|---|
| 0 | `user` | Signer |
| 1 | `user_usdc` | User's cUSDC token account |
| 2 | `user_synth` | User's token account for the pool's synth mint |
| 3 | `pool` | `Pool` PDA |
| 4 | `clp` | PDA `[b"clp", pool.market]`; holds the window cap |
| 5 | `synth_vault` | The pool's synth ATA |
| 6 | `usdc_vault` | The pool's cUSDC ATA |
| 7 | `token_program` | SPL Token |
| 8 | `revenue_attribution` | PDA `[b"revenue_attribution"]` |
| 9 | `market` | The pool's mint-redeem `Market` PDA, read for its risk state and price age; must be last. Added on 11 Oct 2026 |

The pool PDA signs the outbound transfer. Each fill updates `RevenueAttribution` and emits `SwapExecuted` with route 1.

#### `clp_swap(side: u8, direction: u8, amount_in: u64, min_out: u64)` (retired)

Retired on 11 Oct 2026. It was the instant swap against CLP inventory at NAV ± `swap_guards.spread_bps`, with NAV from `Market.user_twap_price`. The instruction keeps its accounts (`user`, `user_usdc`, `user_synth`, `clp`, `clp_vault`, `clp_synth`, `market`, `token_program`) and arguments, so existing clients still decode it, but every call fails with `SwapDisabled`. Use a committed order instead. Its fills emitted `SwapExecuted` with route 0.

#### `commit_swap(side: u8, direction: u8, amount_in: u64, min_out: u64, nonce: u64)` (anyone)

Opens a committed order. It escrows `amount_in` (cUSDC for buys, synth for sells) and sets `expires_at = now + 180`. The user pays rent for the order and escrow accounts and gets it back on every terminal path. The payout account (`user_out`) must already exist, so settlement can't stall on it. It checks `market.is_active` (`MarketInactive`), `swap_guards.enabled` (`SwapDisabled`) and `frozen` (`SwapFrozen`). Accounts: `user`, `market`, `clp`, `order`, `in_mint`, `escrow`, `user_in`, `user_out`, `clp_vault`, `token_program`, `system_program`. Emits `OrderCommitted`.

#### `settle_swap()` (anyone)

Fills a pending order at NAV ± `max(clp.commit_spread_bps, 10)` bps, with NAV from `Market.user_twap_price` at settle time. The keeper cranks it in practice. It requires:

- `now ≤ expires_at`, else `OrderExpired`.
- `market.twap_updated_at > order.created_at`, else `NoFreshOraclePush`. Any push after the commit qualifies, not only the first.
- The oracle guards: not frozen, a price no older than `max_staleness_secs`, and confidence and deviation within limits.

It doesn't recheck `market.is_active` or `swap_guards.enabled`.

| Condition | Result |
|---|---|
| An oracle guard fails | Revert (`SwapFrozen`, `OracleStale`, `OracleConfidenceTooWide` or `OracleDeviationTooLarge`). The order stays pending and can fill at a later push |
| Quote at or above `min_out` | Fill: escrow to the CLP, payout to the user, accounts close. Emits `OrderSettled` and `SwapExecuted` (route 2) |
| Quote below `min_out` | Full refund instead of a revert, so a runaway price can't leave the order retrying until expiry. The accounts close and `OrderRefunded` is emitted |
| Market below `collateral_floor_bps` at the settle price | Revert (`CollateralFloorBreach`). The order stays pending and can fill at a later push once the market is topped up |
| CLP inventory short | Revert. The order stays pending while the keeper adds inventory and retries |

The collateral floor is checked only on the fill path. A fill updates `swap_prev_price` but doesn't count toward the window cap. Accounts: `cranker` (signer), `user` (receives the rent), `order`, `escrow`, `clp`, `clp_vault`, `clp_synth`, `market`, `user_out`, `user_in`, `token_program`.

The keeper posts `commit_spread_bps` with `set_commit_spread`, as `clamp(half-spread, 10, 500)` from its volatility model, and re-posts it whenever it moves by 2 bps or more. As of 10 Oct 2026 it is 18 bps on QQQ, 15 on SPY and 18 on XAU.

#### `cancel_swap()` (anyone, after expiry)

Refunds an expired order once `now > expires_at` (else `OrderNotExpired`). Settle owns `now ≤ expires_at`, so there is no gap or overlap, and before expiry nobody can cancel. Since 11 Oct 2026 anyone may send it: `user` must be the order's owner but doesn't sign, and the escrow can go only to `user_in`, a token account the owner holds for the escrowed mint (`SwapAccountMismatch`). Nothing else is checked (no frozen, enabled, oracle or market-active gate), so escrowed funds can always be recovered after the 180 s TTL. Returns the escrow and all rent to the owner and emits `OrderCancelled`. The keeper sends it for every expired order about 5 s after expiry. Accounts: `user`, `order`, `escrow`, `user_in`, `token_program`.

### Bin book management

#### `init_pool(side: u8, step_bps: u32, num_bins: u8)` (`global_clp.authority`)

Creates the `Pool` PDA, and the signer becomes `pool.authority`. `step_bps` must be in (0, 1000] and `num_bins` in [1, 16]. The pool starts disabled with an empty book.

#### `set_pool_shape(base_price_1e6: u64, asks: Vec<u64>, bids: Vec<u64>)` (`pool.authority`)

The reposition. It sets the centre and every bin's reserve in one call, and sets `enabled = true`. Each vector must have exactly `num_bins` entries and sum to no more than the matching vault balance. The keeper centres the book on NAV shifted for its inventory, with a skewed shape.

#### `configure_pool_geom(wing_step_bps: u32, core_bins: u8)` (`pool.authority`)

Sets the 2-zone geometry. A nonzero `wing_step_bps` must be at least `step_bps`, and `core_bins` at most `num_bins`. `wing_step_bps = 0` restores the uniform ladder.

#### `realloc_pool()` (`pool.authority`)

Grows a pool created before the 2-zone fields existed. The new fields start at 0, which reads as the uniform ladder.

#### `pool_sweep_usdc(amount: u64)` / `pool_sweep_synth(amount: u64)` (`clp.authority`)

Move cUSDC out of a pool's bid vault, or synth out of its ask vault, back to the CLP. One-way buying turns ask inventory into cUSDC that collects in the pool; the sweep recycles it through `vault_mint_pairs` into fresh L+S. The synth sweep trims ask depth far beyond the bid side, and the trimmed synth supplies committed orders instead.

#### `clp_fund_pool_synth(amount: u64)` (`clp.authority`)

Moves synth from the CLP's L or S account into a pool's ask vault, the refill step after `vault_mint_pairs`. No counters change; the next `set_pool_shape` places the tokens in bins.

#### `clp_fund_pool_usdc(amount: u64)` (`clp.authority`)

Moves cUSDC from the market's CLP vault into a pool's bid vault: the bid-side refill. Sell flow spends a book's bid cUSDC. `pool_sweep_synth` takes back the synth the book bought, and this puts the cUSDC back. The source must be the CLP's own vault, the destination must be the pool's cUSDC vault, and the pool must belong to the CLP's market (`SwapAccountMismatch`). No counters change; the next `set_pool_shape` places the cUSDC in bins. Added 11 Oct 2026.

### Inventory minting (`clp.authority`)

The CLP mints and redeems through CPI into mint-redeem, signing as the `Clp` PDA.

- `vault_mint_pairs(usdc_amount: u64)` calls `mint_paired` with cUSDC from the market's CLP vault. The L+S land in the PDA's token accounts, and `vault_l_deployed`/`vault_s_deployed` grow by the amounts actually minted.
- `vault_redeem_pairs(l_amount: u64, s_amount: u64)` burns L+S held by the PDA and returns cUSDC to its vault.
- `vault_redeem_single(is_long: bool, token_amount: u64)` redeems one leg at NAV through mint-redeem's `redeem_single_for_vault`, which refuses to leave the market below 100% collateral.
- `clp_burn_excess(is_long: bool, amount: u64)` burns leftover L or S without any payout, through `permissionless_burn`.

The three vault instructions take 15 accounts. The upgrade of 11 Oct 2026 dropped the trailing `collateral_authority` account, and callers that still send 16 keep working because the extra account is ignored. Each one checks where tokens can go:

- `market` must be this CLP's own market (`MarketMismatch`).
- `clp_vault` must be owned by the `Clp` PDA and hold the market's collateral mint (`InvalidVault`).
- `clp_long_account` and `clp_short_account` must be owned by the `Clp` PDA and hold the market's L and S mints (`InvalidVault`).

### Capital flow

#### `initialize_global_clp(liquidity_seed_threshold: u64)`

One-time setup of `GlobalClp`. The signer becomes `authority`, the `admin_wallet` account is recorded, and the buffer target is set to 1,000 bps. It doesn't create the global vault token account.

#### `admin_fund(amount: u64)` (`global_clp.authority`)

Moves cUSDC from the admin into the global vault, adds it to `total_deposits` and stamps `last_admin_fund_at`.

#### `allocate_to_market(amount: u64)` / `return_to_global(amount: u64)` (`global_clp.authority`)

Move cUSDC between the global vault and a market's CLP vault, updating `allocated_from_global` and `market_allocations`. They move only between those two accounts. The global vault must be owned by the `GlobalClp` PDA, and the CLP vault must be owned by this market's `Clp` PDA and hold the same mint (`InvalidVault`).

#### `deposit_profit(params: DepositProfitParams)`

`DepositProfitParams { amount: u64, source: u8 }`. Moves `amount` of cUSDC out of `keeper_source`, a token account the `keeper` signer controls. A tiered tax goes to `admin_token_account`, which must be owned by `admin_wallet`. The rest goes to the global vault and `total_fees_accumulated`. The tier follows `total_deposits`: 15% below \$5M, 10% up to \$25M and 5% above. The net amount counts as keeper flow in `RevenueAttribution`, under `deposit_by_source[source]` (0 arb, 1 recycled LP fees, 2 yield harvest, 3 other; unknown tags count as 3). Accounts: `global_clp`, `keeper`, `keeper_source`, `global_vault`, `admin_token_account`, `token_program`, `revenue_attribution` (last).

#### `collect_fees(amount: u64)` (`clp.authority`)

Moves fees into the market's CLP vault and adds them to `total_fees_collected`.

#### `vault_record_liquidity_recall(params: VaultRecordLiquidityRecallParams)` (`global_clp.authority`)

Bookkeeping for a legacy Meteora recall; it moves no tokens. `VaultRecordLiquidityRecallParams { l_amount, s_amount, fees_earned }`. It subtracts the amounts from `vault_l_deployed` and `vault_s_deployed` (`InsufficientDeployment` if they're larger). It adds `fees_earned` to `total_meteora_fees_earned`, `total_fees_accumulated`, the protocol buffer and `RevenueAttribution.fees_keeper`. `revenue_attribution` is the last account.

### Treasury

The global vault is the protocol treasury. `admin_withdraw` pays cUSDC out of the protocol, within the limits in `TreasuryPolicy`. `backstop_market` moves cUSDC into a market's collateral and has no limit, because the funds stay inside the protocol. The policy and every instruction below except `admin_withdraw` were added on 11 Oct 2026.

#### `admin_withdraw(amount: u64)` (`global_clp.authority`)

Pays idle cUSDC from the global vault to the policy's `destination`. It works as a token bucket: the allowance refills at `rate_per_sec` up to `burst`, and each withdrawal spends it. A withdrawal must fit in the allowance (`TreasuryAllowanceExceeded`) and in the vault balance (`InsufficientLiquidFunds`), and must pay the policy destination (`InvalidTreasuryDestination`). It is refused while the policy is frozen (`TreasuryFrozen`). Capital allocated to markets must first come back through `return_to_global`.

Accounts: `global_clp`, `authority`, `treasury_policy`, `global_vault` (owned by the `GlobalClp` PDA, else `InvalidVault`), `destination`, `token_program`. Emits `TreasuryWithdrawn`.

On 11 Oct 2026 the bucket replaced the old 24 h cap and the 1 h hold after `admin_fund`, so `AdminWithdrawCapExceeded` (6033) is no longer returned.

#### `init_treasury_policy(params: TreasuryPolicyParams)` (`global_clp.authority`)

`TreasuryPolicyParams { rate_per_sec, burst, delay_secs, guardian, destination }`. Creates `TreasuryPolicy` once, paid for by the signer. The allowance starts at 0. Rate and burst must be above 0, the delay must be 0 to 30 days, and a guardian must be set (`InvalidTreasuryParams`). The `destination` account must be the one named in the params and hold the global vault's mint (`InvalidTreasuryDestination`).

#### `set_treasury_limits(params: TreasuryLimitsParams)` (`global_clp.authority`)

`TreasuryLimitsParams { rate_per_sec, burst, delay_secs, destination, guardian }`, checked like `init_treasury_policy`.

- When every field is equal or tighter, the change applies at once. Tighter means a lower rate, a lower burst, a longer delay, the same destination and the same guardian. Emits `TreasuryLimitsApplied`.
- Any loosening becomes pending until now plus the current `delay_secs`. A new proposal replaces an older pending one. Emits `TreasuryLimitsProposed`.

`TreasuryLimitsProposed` carries `pending_at` and a `loosened` bitmask: 1 rate up, 2 burst up, 4 delay shorter, 8 new destination, 16 new guardian.

#### `apply_treasury_limits()` (anyone)

Applies the pending change once `pending_at` has passed. It fails with `NoPendingTreasuryChange` when nothing is pending and `TreasuryChangeNotReady` before `pending_at`. It also works while frozen.

#### `cancel_treasury_limits()` (`global_clp.authority` or the guardian)

Drops the pending change. Emits `TreasuryLimitsCancelled`.

#### `freeze_treasury()` (the guardian or `global_clp.authority`) and `unfreeze_treasury()` (the guardian only)

Set and clear `frozen`. Both emit `TreasuryFreezeChanged`.

#### `set_treasury_guardian(new_guardian: Pubkey)` (the guardian only)

Hands the guardian role to a new key at once. If a pending change kept the old guardian, it now names the new one, so applying it later can't restore the old key. Emits `TreasuryGuardianSet`.

#### `backstop_market(amount: u64)` (`global_clp.authority`)

Moves treasury cUSDC straight into a market's collateral vault and credits `total_collateral`. It calls mint-redeem's `fund_collateral_from` by CPI, with the `GlobalClp` PDA as funder. The signer is the global authority, which must also be the market's authority. It is not rate limited, because the funds stay inside the protocol, and it works while frozen.

The keeper's liquidity reallocator calls it: at once for a market below 100% collateral at its stored price, and after 5 minutes for one short of its posted target by more than one confidence band. It fills to the posted target, at most 112% (102% for MSTR), and never takes a fill back. See [Solvency → Treasury backstop](/concepts/solvency#treasury-backstop).

Accounts: `global_clp`, `authority`, `market`, `collateral_vault` (the market's), `global_vault`, `mint_redeem_program`, `token_program`. Emits `MarketBackstopped`, and mint-redeem emits `CollateralFunded`.

### Configuration

- `initialize_clp(oi_cap: u64, oracle_config: Pubkey)` creates a market's `Clp` with the default inventory budget, yield off and zeroed swap guards. The signer must be the Market's `authority` and becomes `clp.authority`.
- `configure_swap(params: ConfigureSwapParams)` (`clp.authority`) sets `SwapGuardsState`. `ConfigureSwapParams { enabled, frozen, spread_bps, max_staleness_secs, max_confidence_bps, max_deviation_bps, window_cap_usd, window_secs, collateral_floor_bps }` holds the separate arguments the instruction took until 11 Oct 2026, with the same fields in the same order, so the bytes on the wire are unchanged. Every field is optional, and `None` leaves it unchanged. `frozen = true` stops `commit_swap` and `settle_swap`, but not `pool_swap` or `cancel_swap`.
- `set_commit_spread(commit_spread_bps: u16)` (`clp.authority`) sets the committed-order half-spread. `settle_swap` floors it at 10 bps.
- `update_oi_cap(new_cap: u64)` (`clp.authority`) sets the stored OI cap, which nothing enforces.
- `configure_inventory_budget(params: ConfigureInventoryBudgetParams)` and `configure_yield_strategy(params: ConfigureYieldStrategyParams)` (`clp.authority`) set the inventory bounds and the yield shares. Each struct holds the instruction's former arguments as optional fields, in the same order, so the bytes on the wire are unchanged: `ConfigureInventoryBudgetParams { soft_lower_bps, soft_upper_bps, hard_lower_bps, hard_upper_bps, max_drawdown_bps, target_drawdown_bps, enforce_hard_bounds }` and `ConfigureYieldStrategyParams { normal_deployment_bps, proxy_deployment_bps, stress_deployment_bps, recovery_deployment_bps, min_liquid_reserve, min_liquid_reserve_bps, oi_liquidity_buffer_bps, enabled }`.
- `configure_liquidity_seeder(threshold: Option<u64>)` and `realloc_clp()` (`global_clp.authority`) set the seed threshold and grow an older `Clp` to the current layout.
- `init_revenue_attribution(params: RevenueAttributionParams)` and `configure_revenue_attribution(params: RevenueAttributionParams)` (`global_clp.authority`) create the `RevenueAttribution` singleton and replace its `keeper_authorities`. `RevenueAttributionParams` is `{ keeper_authorities: [Pubkey; 4] }`. Configuring leaves the counters and `started_at` alone.

### Inventory checks

- `update_inventory(volatile_value: u64, stable_value: u64)` (`clp.authority`) recomputes q, drawdown and the breach flags.
- `update_oi(new_oi: u64)` (`clp.authority`) sets `current_oi` and fails with `OICapExceeded` above `oi_cap`. Nothing calls it today.
- `check_inventory_restrictions()` returns `hard_breach && enforce_hard_bounds`, and `get_yield_status()` returns `(total_deployed, max_deployable, can_deploy_more)`. Both are read-only and CPI-callable.

### Yield (off)

`record_deployment` and `record_withdrawal` (`clp.authority`) and `record_harvest` (`global_clp.authority`) track deployments to lending venues. `add_yield_to_buffer` and `absorb_loss` (`global_clp.authority`) maintain the global protocol buffer. Yield is off by default (`yield_strategy.enabled = false`).

### Legacy Meteora instructions

`configure_meteora_pools`, `clear_meteora_positions`, `clp_set_meteora_position`, `clp_init_bin_array`, `clp_open_meteora_position`, `clp_topup_meteora_position`, `clp_remove_meteora_liquidity`, `clp_claim_lp_fees` and `clp_close_meteora_position` managed the v1 Meteora positions. They are legacy: every market now trades on native bin books. `InvalidPool`, `PoolNotConfigured` and most `InvalidPosition` errors come only from these instructions. `clp_remove_meteora_liquidity` and `clp_claim_lp_fees` pay only token accounts owned by the `Clp` PDA (`InvalidVault`).

## Events

`commit_swap` emits `OrderCommitted`, `settle_swap` emits `OrderSettled` or `OrderRefunded`, and `cancel_swap` emits `OrderCancelled`. The treasury instructions emit `TreasuryPolicyInitialized`, `TreasuryWithdrawn`, `TreasuryLimitsProposed`, `TreasuryLimitsApplied`, `TreasuryLimitsCancelled`, `TreasuryFreezeChanged`, `TreasuryGuardianSet` and `MarketBackstopped`. Their fields are in the IDL. Every fill on any route also emits `SwapExecuted`:

| Field | Type | Meaning |
|---|---|---|
| `user` | Pubkey | Swap signer, or the order's owner for a committed fill |
| `market` | Pubkey | Market PDA |
| `collateral_mint` / `synth_mint` | Pubkey | cUSDC and the traded leg |
| `order` | Pubkey | Order PDA for a committed fill; default pubkey otherwise |
| `route` | u8 | 0 = `clp_swap` (retired), 1 = `pool_swap`, 2 = `settle_swap` fill |
| `side` / `direction` | u8 | 0 = long, 1 = short / 0 = buy synth, 1 = sell synth |
| `is_keeper` | bool | `user` is a keeper key: `clp.authority` or a `keeper_authorities` entry on route 1, `clp.authority` or `Market.keeper_authority` on routes 0 and 2 |
| `amount_in` / `amount_out` | u64 | Base units in and out |
| `collateral_amount` / `synth_amount` | u64 | The same two amounts, by token |
| `reference_price` | u64 | NAV (1e6) on routes 0 and 2; the book centre on route 1 |
| `spread_capture` | u64 | Execution spread against `reference_price`, in cUSDC base units. It isn't realized revenue |

## TypeScript

This reads QQQ's long book and builds a `pool_swap` that spends up to 10 cUSDC on QQQ-L. `provider` is set up as in [SDK setup](/build/sdk-setup), and the IDL is published in [`continuum-docs/idl`](https://github.com/continuum-markets/continuum-docs/tree/main/idl).

```typescript
import { BN, Program } from "@coral-xyz/anchor";
import { PublicKey } from "@solana/web3.js";
import { getAssociatedTokenAddressSync, TOKEN_PROGRAM_ID } from "@solana/spl-token";
import clpIdl from "./clp.json";

const clp: any = new Program(clpIdl as any, provider);
const pda = (...seeds: Buffer[]) => PublicKey.findProgramAddressSync(seeds, clp.programId)[0];

const market = new PublicKey("F12ostJBgYCzsdouwz5GG1qeBCwbmhNGucPBNCZCfPG5"); // QQQ
const clpPda = pda(Buffer.from("clp"), market.toBuffer());
const longPool = pda(Buffer.from("pool"), market.toBuffer(), Buffer.from([0])); // 0 = long
const revenueAttribution = pda(Buffer.from("revenue_attribution"));

const [perMarket, pool] = await Promise.all([
  clp.account.clp.fetch(clpPda),
  clp.account.pool.fetch(longPool),
]);

// Anchor renders base_price_1e6 as basePrice1E6 (capital E).
console.log("Book centre:", pool.basePrice1E6.toNumber() / 1e6);
console.log("Committed spread (bps):", Math.max(perMarket.commitSpreadBps, 10));
console.log("Swap guards enabled:", perMarket.swapGuards.enabled);

// Build a pool_swap that spends up to 10 cUSDC on QQQ-L.
// The pool's vaults are the pool PDA's associated token accounts.
const user = provider.publicKey;
const ix = await clp.methods
  .poolSwap({ direction: 0, amountIn: new BN(10_000_000), minOut: new BN(1) }) // set minOut from your own quote
  .accountsStrict({
    user,
    userUsdc: getAssociatedTokenAddressSync(pool.usdcMint, user),
    userSynth: getAssociatedTokenAddressSync(pool.synthMint, user),
    pool: longPool,
    clp: clpPda,
    synthVault: getAssociatedTokenAddressSync(pool.synthMint, longPool, true),
    usdcVault: getAssociatedTokenAddressSync(pool.usdcMint, longPool, true),
    tokenProgram: TOKEN_PROGRAM_ID,
    revenueAttribution,
    market, // the mint-redeem Market, last
  })
  .instruction();
```

On 10 Oct 2026 the read printed a centre of 751.27, a committed spread of 18 bps and `true` for the swap guards. A simulation of the instruction filled 10 cUSDC for 0.013257 QQQ-L. That was a Saturday, with QQQ's price stale; while its price is live, the same instruction fails with `PoolClosedWhileLive`. Send it in a transaction that first creates the user's synth ATA if it doesn't exist.
